# Локальный запуск

Полный стек на своей машине одной командой: приложение, PostgreSQL, перехватчик
почты и мониторинг (Prometheus + Grafana). Продакшен-деплой при этом не меняется:
всё локальное живёт в отдельных файлах и в отдельном compose-проекте
`healthlogin-local`.

## Быстрый старт

```bash
make local-up
```

При первом запуске цель сама создаст `.env.local` из `.env.local.example` и
сгенерирует самоподписанный сертификат `certs/localhost-*.pem`, если его нет.
Уже существующий `.env.local` не перезаписывается, даже если шаблон обновился:
новые переменные из шаблона переносите вручную.
Сборка образов при первом запуске занимает несколько минут.

После старта:

| Сервис | Адрес | Доступ |
| :--- | :--- | :--- |
| Фронтенд (SPA + API через nginx) | https://localhost:8443 | самоподписанный сертификат — принять предупреждение браузера |
| Бэкенд напрямую (TLS) | https://localhost:8088 | — |
| Mailpit (вся исходящая почта) | http://127.0.0.1:8025 | без пароля |
| Grafana | http://127.0.0.1:3000 | `admin` / `admin` (из `.env.local`) |
| Prometheus | http://127.0.0.1:9090 | — |
| PostgreSQL | `127.0.0.1:5432` | `healthlogin` / `healthlogin`, `make local-psql` |

Остальные команды:

```bash
make local-logs    # логи всех сервисов
make local-psql    # psql в локальную базу
make local-down    # остановить стек (данные в volume'ах сохраняются)
```

## Чем локальный стек отличается от продакшен-стека

Все отличия намеренные и собраны в `docker-compose.local.yml`:

- **Почта.** Вместо maddy поднимается [Mailpit](https://mailpit.axllent.com/):
  письма (подтверждение почты, код сброса пароля) наружу не уходят, а читаются
  в веб-интерфейсе на `:8025`. SMTP без аутентификации — `mailer.go` это умеет.
- **База.** Postgres опубликован на `127.0.0.1:5432` для psql, IDE и go-утилит
  (в проде порт не публикуется вовсе). Порт на хосте меняется переменной
  `LOCAL_DB_PORT` в `.env.local` — пригодится, если 5432 занят другим Postgres'ом.
- **TLS.** nginx терминирует HTTPS самоподписанным сертификатом
  (`nginx.local.conf`, `server_name localhost`), а не боевым сертификатом
  домена. HSTS локально отключён. Свой доверенный сертификат (например, от
  mkcert) можно просто положить в `certs/localhost-cert.pem` /
  `certs/localhost-key.pem` — `make local-certs` существующие файлы не трогает.
- **Мониторинг.** Облегчённый: Prometheus, Grafana, postgres-exporter,
  nginx-exporter. Alertmanager, ops-бот, node-exporter, cadvisor и
  blackbox-проверки боевого домена не поднимаются — они про продакшен и
  Telegram-алерты. Дашборды Grafana те же, что в проде
  (`monitoring/grafana/dashboards`); панели по отсутствующим job'ам пустые.
- **Секреты.** Всё необходимое имеет dev-дефолты в `.env.local.example`
  (JWT-secret, пароль БД, пароль Grafana). Эти значения только для локальной
  разработки; на сервер они не попадают — деплой по-прежнему использует `.env`
  (шаблон `.env.deploy.example`).

## Переменные окружения

Локальный стек читает только `.env.local` (явный `--env-file` отключает
автозагрузку `.env`, поэтому боевые секреты не подхватываются, даже когда `.env`
лежит рядом). Полный список переменных с комментариями — в
[`.env.local.example`](../.env.local.example). Единственная содержательная
настройка:

- `DADATA_API_KEY` — ключ DaData для подсказок адресов. Без него стек работает,
  но `/geo/suggest` отвечает 503 и регистрацию до конца пройти нельзя.

## Ограничения и частые вопросы

- **Порты общие с прод-образным стеком** (`docker-compose.yml`, `make start`):
  одновременно они не работают. Перед `make local-up` выполните `make stop`.
- **Данные** лежат в отдельных volume'ах (`postgres_local_data` и др.) и не
  пересекаются с прод-образными. Полный сброс: `make local-down`, затем
  `docker volume rm healthlogin-local_postgres_local_data`.
- **Миграции** применяет бэкенд при старте, как в проде; отдельный шаг не нужен.
- **pg_stat_statements** включён на уровне сервера; само расширение создаётся
  один раз: `docker exec healthlogin_local_db psql -U healthlogin -d healthlogin -c "CREATE EXTENSION IF NOT EXISTS pg_stat_statements;"`.
