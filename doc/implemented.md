# Что реализовано в текущей версии

## 1. Бэкенд (Go)

### HTTP-обработчики
* Все handlers вынесены в пакет `backend/handler/`:
  * `public.go` — публичные endpoints: `/health`, `/register`, `/login`.
  * `admin.go` — управление пользователями, финансами, настройками.
  * `order.go` — создание/подтверждение/отмена заказов, поиск заказов рядом.
  * `shift.go` — смены и GPS-телеметрия.
  * `bid.go` — ставки на строительные заказы.
  * `chat.go` — WebSocket и сообщения.
  * `geo.go` — подсказки и геокодирование адресов.
* CORS настроен для веба и мобильных origin (`http://localhost`, `capacitor://localhost` и др.).

### Авторизация
* Регистрация с адресом забора мусора: принимаются и части адреса, и одна строка (для уже установленных клиентов). Проверка смысловая — нужны населённый пункт, улица и дом; прежнее регулярное выражение с числовым номером дома убрано, поэтому `12к1` и `10 стр. 2` больше не отклоняются.
* JWT access-токен (15 минут) с claims `sub`, `phone`, `role`.
* Middleware поддерживает токены из заголовка `Authorization: Bearer` и Cookie `token`.
* Logout с добавлением токена в чёрный список (`token_blacklist`).

### Пользователи и профили
* `customer_profiles` с полями `full_name`, `address`, `last_geo`, а также `address_flat`, `address_fias_id`, `address_lat`, `address_lon`.
* Сохранённые адреса заказчика в `customer_addresses` — частями (`city`, `street`, `house`, `flat`, `fias_id`, координаты, `source`): `POST /user/address`, `POST /user/address/default`, `DELETE /user/address/{id}`.
* Администратор может изменить адрес заказчика через `POST /admin/users/{id}/address`.
* Профиль возвращается через `GET /customer/profile`.

### Финансы и настройки
* Ручное пополнение баланса администратором.
* Заявки на пополнение с одобрением/отклонением.
* `system_settings` хранит строковые значения: коэффициенты тарифов, штраф, валюта.
* Публичный endpoint `GET /settings` возвращает текущую валюту.

### Заказы
* Создание обычных заказов с расчётом цены.
* Автоматический мэтчинг по геолокации (5 сек).
* Холдирование средств и возврат/выплата при завершении.
* SLA-даунгрейд для `ASAP`/`URGENT` при просрочке.
* Аукционная модель для строительного мусора.
* Особые услуги на скриптах: правила услуги (кому видна, сколько стоит, сколько раз заказывается, что делать по событию) живут в Starlark-скрипте `backend/behaviors/*.star`, а не в коде. Первая такая услуга — верификация аккаунта: бесплатна, видна только неверифицированным, заказывается один раз, выполняется только модератором, закрывается автоматически при верификации и платит верификатору вознаграждение со счёта `BONUSES`. Доменные события пишутся в outbox `domain_events` в одной транзакции с изменением состояния, эффекты применяет ядро.
* Проверка личности в услуге верификации: модератору видно только адрес (ни телефона, ни ФИО, ни даты рождения), он вводит данные с документа, платформа сверяет их с аккаунтом и отдаёт скрипту лишь результат сравнения. Первое несовпадение — предупреждение сверить с паспортом, повторное — заказ уходит на модерацию администратора (`POST /executor/orders/{id}/submission`, экран «Модерация проверок»).
* Редактор скриптов в конструкторе услуг: флаг «Спец-услуга» открывает два поля — константы и сам скрипт, с шаблонами из поставляемой библиотеки и ссылкой на страницу-инструкцию `/admin/service-scripts`. Скрипт компилируется до записи в базу: сломанный не сохраняется (см. [`service_behaviors.md`](./service_behaviors.md)).
* Подсказки адресов через **DaData** (`GET /geo/suggest`) — с раздельными частями (город, улица, дом, квартира, `fias_id`) и координатами прямо в подсказке.
* Legacy-автодополнение (`GET /geo/autocomplete`) сохранено для установленных мобильных сборок — источник данных тот же DaData.
* Геокодирование произвольных строк через OpenStreetMap Nominatim (`GET /geo/geocode`) с кэшем в таблице `geocoding_cache`.
* Рейт-лимит на гео-эндпоинты: 30 запросов в минуту.

### Смены и геозоны
* Открытие смен 1/3/5 часов.
* Автооткрытие смены при взятии заказа: исполнитель, нажавший «взять заказ» без активной смены, получает её автоматически. Смена открывается только после того, как заказ прошёл все проверки, и закрывается обратно (без штрафа), если назначение сорвалось. Настройки `auto_shift_on_accept_enabled` и `auto_shift_duration_hours`, миграция `046`. См. [`order_lifecycle.md`](./order_lifecycle.md#3-автооткрытие-смены-при-взятии-заказа).
* GPS-логи в `shift_gps_logs`.
* Проверка круглых и полигональных геозон.
* Штрафы за нарушение геозоны.

### Чат
* WebSocket-чат между заказчиком и исполнителем в рамках заказа.
* Блокировка записи после завершения/отмены.

### Фоновые воркеры
* MatchingWorker — автоматическое назначение заказов.
* SLAWorker — даунгрейд и контроль сроков.
* AuctionWorker — отмена старых аукционов (7 дней).

## 3. Фронтенд (Vue 3 SPA)

* Маршрутизация с ролевой защитой.
* Локализация `ru`/`en` через `vue-i18n`.
* Страница авторизации с переключением языка.
* Админ-панель: пользователи, пополнения, транзакции, настройки (включая валюту).
* Панель заказчика: баланс, создание заказа с выбором типа, история заказов, чат.
* Панель исполнителя: смены, поиск заказов рядом, ставки, чат.
* Кэш «сначала показать, потом догрузить»: заказы, история, смена и профиль поднимаются из `localStorage` синхронно при открытии экрана, сеть уточняет их следом. Кэш привязан к пользователю, живёт 12 часов и стирается вместе с сессией (`services/cache.ts`, `composables/useCachedResource.ts`).
* Прелоадеры: скелетоны списков (`SkeletonList.vue`) там, где показывать ещё нечего, и значок тихой догрузки (`RefreshingBadge.vue`) поверх уже показанных данных.
* Предзагрузка изображений (`services/orderImages.ts`): фотографии из чатов активных заказов прогреваются последней ступенью очереди и хранятся, пока заказ не закроется; закрытие заказа освобождает блобы явным `revokeObjectURL`. Пути к вложениям переживают перезапуск, поэтому холодный старт не ждёт сообщений чата.
* Приоритеты загрузки (`utils/loadPriority.ts`): сетевые запросы экрана уходят ступенями — сначала смена и активные заказы, затем профиль и списки, история заказов (и оценки к завершённым) — самой последней. Кэш при этом поднимается у всех ресурсов сразу, поэтому приоритет распределяет сеть, а не показ. Подробно — [`frontend_data_loading.md`](./frontend_data_loading.md).

## 4. Мобильное приложение

* Capacitor 6 Android.
* Нативный HTTP для обхода WebView-ограничений.
* URL API в нативной сборке берётся только из `VITE_MOBILE_API_URL`/`VITE_API_URL`; захардкоженный fallback убран — неверный адрес выглядел бы как «бэкенд лежит».
* Индикатор состояния сервера.
* Языковой переключатель на экране заказчика.
