# Что реализовано в текущей версии

## 1. Бэкенд (Go)

### HTTP-обработчики
* Все handlers вынесены в пакет `backend/handler/`:
  * `public.go` — публичные endpoints: `/health`, `/register`, `/login`.
  * `admin.go` — управление пользователями, финансами, настройками.
  * `order.go` — создание/подтверждение/отмена заказов, поиск заказов рядом.
  * `shift.go` — смены и GPS-телеметрия.
  * `bid.go` — ставки на строительные заказы.
  * `chat.go` — WebSocket и сообщения.
  * `geo.go` — геокодирование адресов.
* CORS настроен для веба и мобильных origin (`http://localhost`, `capacitor://localhost` и др.).

### Авторизация
* Регистрация с адресом забора мусора.
* JWT access-токен (15 минут) с claims `sub`, `phone`, `role`.
* Middleware поддерживает токены из заголовка `Authorization: Bearer` и Cookie `token`.
* Logout с добавлением токена в чёрный список (`token_blacklist`).

### Пользователи и профили
* `customer_profiles` с полями `full_name`, `address`, `last_geo`.
* Администратор может изменить адрес заказчика через `POST /admin/users/{id}/address`.
* Профиль возвращается через `GET /customer/profile`.

### Финансы и настройки
* Ручное пополнение баланса администратором.
* Заявки на пополнение с одобрением/отклонением.
* `system_settings` хранит строковые значения: коэффициенты тарифов, штраф, валюта.
* Публичный endpoint `GET /settings` возвращает текущую валюту.

### Заказы
* Создание обычных заказов с расчётом цены.
* Автоматический мэтчинг по геолокации (5 сек).
* Холдирование средств и возврат/выплата при завершении.
* SLA-даунгрейд для `ASAP`/`URGENT` при просрочке.
* Аукционная модель для строительного мусора.
* Геокодирование адресов через Nominatim.

### Смены и геозоны
* Открытие смен 1/3/5 часов.
* GPS-логи в `shift_gps_logs`.
* Проверка круглых и полигональных геозон.
* Штрафы за нарушение геозоны.

### Чат
* WebSocket-чат между заказчиком и исполнителем в рамках заказа.
* Блокировка записи после завершения/отмены.

### Фоновые воркеры
* MatchingWorker — автоматическое назначение заказов.
* SLAWorker — даунгрейд и контроль сроков.
* AuctionWorker — отмена старых аукционов (7 дней).

## 2. База данных

Схема PostgreSQL с миграциями в `backend/migrations/`:
* `001_create_enums.sql` — ENUM-типы.
* `002_create_tables.sql` — базовые таблицы.
* `003_admin_finances.sql` — финансовые сущности.
* `004_geozones_and_orders.sql` — геозоны и дополнительные поля заказов.
* `005_order_pickup_and_executor_radius.sql` — координаты заказов и радиус поиска исполнителя.
* `006_settings_currency.sql` — строковые настройки и валюта.
* `007_customer_address_string.sql` — адрес заказчика как строка.
* `008_rename_fine_amount.sql` — переименование штрафа в `geofence_fine_amount`.

## 3. Фронтенд (Vue 3 SPA)

* Маршрутизация с ролевой защитой.
* Локализация `ru`/`en` через `vue-i18n`.
* Страница авторизации с переключением языка.
* Админ-панель: пользователи, пополнения, транзакции, настройки (включая валюту).
* Панель заказчика: баланс, создание заказа с выбором типа, история заказов, чат.
* Панель исполнителя: смены, поиск заказов рядом, ставки, чат.

## 4. Мобильное приложение

* Capacitor 6 Android.
* Нативный HTTP для обхода WebView-ограничений.
* Индикатор состояния сервера.
* Языковой переключатель на экране заказчика.

## 5. Деплой

* `docker-compose.yml` для локальной разработки с persistent volume `postgres_data`.
* `docker-compose.prod.yml` для продакшена.
* GitHub Actions workflow для автодеплоя.
