# Панель администратора (Admin Control & Operational Management)

Документ содержит подробное описание всех функций административной панели бэкенда и веб-интерфейса.

---

## 1. Функциональные модули

Панель администратора состоит из 6 ключевых разделов:

1. **Пользователи (`/admin/users`)**
2. **Заявки на пополнение (`/admin/topups`)**
3. **История транзакций (`/admin/transactions`)**
4. **Активные смены (`/admin/shifts`)**
5. **Активные и завершенные заказы (`/admin/orders`)**
6. **Системные настройки и тарифы (`/admin/settings`)**

---

## 2. Разделы и эндпоинты

### 2.1 Управление пользователями (`UserList.vue`)

- **Просмотр списка**: Пагинация, фильтрация по ролям (`CUSTOMER`, `EXECUTOR`, `ADMIN`), статусам (`ACTIVE`, `BANNED`) и поисковой строке по телефону/имени.
- **Изменение статуса**: Блокировка/разблокировка пользователей (`POST /api/admin/users/{id}/status`).
- **Изменение роли**: Смена прав пользователя (`POST /api/admin/users/{id}/role`).
- **Ручное изменение адреса**: Редактирование адреса забора мусора у заказчиков (`POST /api/admin/users/{id}/address`). Эндпоинт принимает обе формы: части адреса (`city`, `street`, `house`, `flat`, `fias_id`, `lat`/`lon`, `source`) и одну строку `address` — во втором случае она раскладывается на сервере. Админка пока шлёт строку. См. [`address_suggestions.md`](./address_suggestions.md).

```http
POST /api/admin/users/c7a8f9e0-1234-5678-9abc-def012345678/status
Content-Type: application/json

{
  "status": "BANNED"
}
```

### 2.2 Заявки на пополнение баланса (`TopUpRequests.vue`)

В текущей версии ручное пополнение происходит по заявкам:
- **`GET /api/admin/topup-requests?status=PENDING`** — список нерассмотренных заявок.
- **`POST /api/admin/topup-requests/{id}/approve`** — подтверждение заявки (баланс заказчика увеличивается, создается финансовая транзакция `TOPUP`).
- **`POST /api/admin/topup-requests/{id}/reject`** — отклонение заявки.

### 2.3 Мониторинг смен исполнителей (`ActiveShifts.vue`)

- **`GET /api/admin/shifts`** — отображение всех активных и завершенных смен с текущими статусами (`ACTIVE`, `COMPLETED`, `PENALIZED`).
- Индикация количества нарушений геозоны и штрафов.

### 2.4 Системные настройки (`SystemSettings.vue`)

Администратор управляет ключевыми параметрами работы приложения через `system_settings`:

| Ключ настройки | Тип | Описание |
| :--- | :--- | :--- |
| `currency` | `STRING` | Валюта отображения в приложении (`RUB`, `USD`, `EUR`). |
| `tariff_increased_mult` | `FLOAT` | Множитель тарифа «Увеличенный объем» (по умолчанию `2.0`). |
| `tariff_urgent_mult` | `FLOAT` | Множитель тарифа «Срочный (1 час)» (по умолчанию `3.0`). |
| `tariff_asap_mult` | `FLOAT` | Множитель тарифа «ASAP (15 минут)» (по умолчанию `8.0`). |
| `geofence_penalty_amount` | `FLOAT` | Сумма штрафа за нарушение геозоны смены. |
| `early_exit_penalty_amount` | `FLOAT` | Сумма штрафа за досрочное завершение смены. |
| `min_balance_limit` | `FLOAT` | Лимит отрицательного баланса (ухода в минус) исполнителя (по умолчанию `0`). |
| `order_commission_percent` | `FLOAT` | Комиссия платформы с выполненного заказа, в процентах, `0..100` (по умолчанию `0`). |
| `behavior_max_bonus` | `FLOAT` | Потолок одной выплаты, назначенной скриптом услуги, в рублях (по умолчанию `5000`). См. [`service_behaviors.md`](./service_behaviors.md). |

### 2.5 Комиссия платформы (`PlatformCommission.vue`)

- **`GET /api/admin/finances/commission`** — накопленный остаток системного счёта `COMMISSION` и действующая ставка.
- **`POST /api/admin/finances/commission/payout`** — вывод накопленного из системы, тело `{ "amount": <рубли> }`.

Оба маршрута доступны только роли `ADMIN`; вывод ограничен остатком счёта, а
идентификатор администратора записывается в журнал операции. Как считается сама
комиссия — в [`financial_system.md`](./financial_system.md#4b-комиссия-платформы).

### 2.6 Конструктор услуг: особое поведение (`ServiceNodeForm.vue`)

Узлу каталога можно назначить **поведение** — скрипт, который несёт правила
услуги, не выражаемые флагами: кому она видна, сколько стоит, можно ли заказать
её повторно, что происходит при выполнении.

- **`GET /api/admin/service-behaviors`** — список загруженных поведений: код, имя,
  описание, события, значения настроек по умолчанию. Список строится из самих
  скриптов, поэтому новое поведение появляется в панели сразу после деплоя файла.
- В форме услуги — выпадающий список «Особое поведение» и JSON-редактор настроек;
  при выборе поведения подставляются его значения по умолчанию, и задавать нужно
  только отличия.
- Узел с неизвестным `behavior_code` не сохраняется: такой код молча снял бы
  услугу с продажи, потому что все её проверки начали бы отказывать.

Механизм целиком, вместе с услугой верификации, описан в
[`service_behaviors.md`](./service_behaviors.md).

### 2.7 Чат поддержки клиентов (`AdminSupportChats.vue`)

- **`GET /api/admin/support/chats`** — получение списка всех пользовательских диалогов с нечитанными сообщениями, ФИО, телефоном и ролью.
- **`GET /api/support/chats/{chat_id}/messages`** — история диалога с клиентом.
- **`POST /api/support/chats/{chat_id}/messages`** — отправка текстового ответа сотрудника поддержки.
- **`POST /api/support/chats/{chat_id}/upload`** — загрузка медиа и вложений.
