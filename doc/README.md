# Платформа сервиса по выносу мусора (On-Demand)

## Описание проекта

Маркетплейс услуг по выносу мусора, работающий по модели «по требованию» (on-demand). Платформа связывает заказчиков с исполнителями, работающими по гибкому сменному графику.

### Ключевые особенности системы
* **Гибкая тарификация:** стандартные заявки и срочный вынос с настраиваемыми коэффициентами.
* **Строительный мусор:** аукционная модель с торгами между заказчиками и исполнителями.
* **Внутренний баланс:** виртуальные кошельки с холдированием средств на время выполнения заказа.
* **Геолокация и мэтчинг:** поиск ближайших заказов и исполнителей на основе координат.
* **SLA-контроль:** автоматические штрафы за выход из геозоны и даунгрейд тарифов при нарушении сроков.

### Технологический стек
* **Бэкенд:** Go 1.26 (Chi, JWT, SQL)
* **База данных:** PostgreSQL 16
* **Фронтенд:** Vue 3 + Vite + Pinia + Vuestic UI + vue-i18n
* **Мобильное приложение:** Capacitor 6 + Android
* **Деплой:** Docker Compose + GitHub Actions

## 1. Ролевая модель

| Роль | Функции | Требования при регистрации |
| :--- | :--- | :--- |
| **Заказчик** | Создание заказов, пополнение баланса, подтверждение выполнения. | Телефон, пароль, адрес забора мусора. |
| **Исполнитель** | Выход на смены, выполнение заказов в закрепленном районе. | Телефон, пароль. |
| **Администратор** | Модерация пользователей, ручное пополнение баланса, настройка тарифов и валюты, изменение адресов заказчиков. | Предустановленная учётная запись. |

## 2. Авторизация и аутентификация

* Идентификатор — номер телефона (уникален в системе).
* Пароль хешируется `bcrypt`.
* Access-токен JWT (`HS256`, 15 минут) с claims: `sub`, `phone`, `role`.
* Выход (`POST /logout`) добавляет текущий токен в чёрный список.
* Все ошибки аутентификации возвращают `invalid credentials` (401).

### Основные endpoints
| Метод | Путь | Назначение |
| :--- | :--- | :--- |
| POST | `/register` | Регистрация заказчика с адресом |
| POST | `/login` | Вход и получение JWT |
| POST | `/logout` | Отзыв текущего токена |
| GET | `/health` | Проверка работоспособности |
| GET | `/settings` | Публичные настройки (валюта) |
| GET | `/geo/autocomplete?q=...` | Подсказки адресов (Nominatim) |
| GET | `/geo/geocode?q=...` | Геокодирование адреса |

## 3. Финансовая логика

* **Баланс:** предоплата на внутреннем кошельке.
* **Пополнение:** в MVP — через запрос администратору, который одобряет или отклоняет заявку.
* **Холдирование:** сумма заказа блокируется при создании.
* **Выплата:** исполнителю начисляется после подтверждения заказчиком.
* **Валюта:** настраивается в админке (`RUB` по умолчанию).

### Тарифная сетка
| Тип | Описание | Коэффициент |
| :--- | :--- | :--- |
| Standard | Обычный вывоз | ×1 |
| Increased | Увеличенный объём | ×2 (настраивается) |
| Urgent | Срочный (1 час) | ×3 (настраивается) |
| ASAP | Немедленный (15 минут) | ×8 (настраивается) |
| Construction | Договорная цена через аукцион | — |

## 4. Заказы и мэтчинг

### Обычные заказы
1. Заказчик выбирает тип объёма (`STANDARD`, `LARGE`) и тариф.
2. Система рассчитывает цену по базовой цене и коэффициенту.
3. При создании заказа указывается адрес из профиля; координаты определяются через геокодер Nominatim.
4. Фоновый воркер каждые 5 секунд ищет активного исполнителя в радиусе 2 км и назначает заказ.

### Строительный мусор
1. Заказчик создаёт заявку с фото, без фиксированной цены.
2. Исполнители делают ставки.
3. Заказчик принимает ставку; средства холдируются.
4. Заявка автоматически отменяется через 7 дней, если не востребована.

## 5. Операционная деятельность исполнителей

* **Смены:** 1, 3 или 5 часов.
* **Геозоны:** круглые и полигональные зоны; проверка по Haversine-формуле и Ray-Casting.
* **Штрафы:** при 3-х последовательных отметках вне геозоны списывается штраф, смена переходит в статус `PENALIZED`.
* **Поиск заказов:** исполнитель может запросить список ближайших заказов вручную или получить назначение автоматически.

## 6. Панель администратора

* Управление пользователями (статус, роль, баланс, адрес).
* Заявки на пополнение баланса.
* История транзакций.
* Глобальные настройки: коэффициенты тарифов, штраф за геозону, валюта.

---

## 7. Чат заказчик ↔ исполнитель

* Привязан к заказу: одна комната на заказ, участники — заказчик и назначенный исполнитель.
* Веб: чистый WebSocket (приём + отправка в реальном времени).
* Мобильное приложение (Android/Capacitor): WebSocket primary + HTTP REST fallback (отправка через `POST`, приём через поллинг каждые 3с) — обход нестабильности WS в WebView.
* Блокировка при `COMPLETED`/`CANCELED`; системные события `lock`/`downgrade`.
* Подробное описание: [`chat.md`](./chat.md).

---

## 8. Мобильное приложение

* Сборка через Capacitor (`make build-android`).
* Используется нативный HTTP (`CapacitorHttp`) для обхода CORS/mixed-content в WebView.
* Поддержка русского и английского языков.
* Индикатор состояния сервера в правом верхнем углу.

---

## 9. Деплой

* **Локально:** `docker compose up -d --build`.
* **Продакшен:** `docker-compose.prod.yml` + `.env`.
* **CI/CD:** GitHub Actions (`.github/workflows/deploy.yml`) собирает образы, пушит в Docker Hub и деплоит на сервер по SSH.
