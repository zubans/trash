# Геолокация и авто-мэтчинг (Geolocation & Matching)

Документ описывает геопространственную логику платформы: геокодирование адресов, авто-мэтчинг заказов и отчёт о местоположении исполнителя на смене.

---

## 1. Адреса и координаты

Подсказки адресов выдаёт **DaData**, которая возвращает координаты вместе с подсказкой — отдельный запрос геокодирования после выбора адреса больше не нужен. Nominatim больше не используется.

- **`GET /api/geo/suggest?q=...&count=7`** — подсказки адресов с раздельными частями (город, улица, дом, квартира, `fias_id`, `lat`/`lon`). Основной эндпоинт.
- **`GET /api/geo/autocomplete?q=...`** — legacy-форма ответа одной строкой, сохранена ради уже установленных мобильных сборок. Источник данных — тоже DaData.
- **`GET /api/geo/geocode?q=...`** — перевод строки адреса в широту и долготу (`latitude`, `longitude`): кэш `geocoding_cache`, затем лучшая подсказка DaData с координатами (`AddressSuggester.Resolve`).

Все три эндпоинта ограничены рейт-лимитером: **30 запросов в минуту**. Коды ошибок: `503` — провайдер не настроен, `429` — провайдер занят, `422` — прочее.

Адрес хранится частями (миграция `031_structured_addresses.sql`), а не одной строкой, поэтому адреса, добавленные из профиля, имеют координаты и участвуют в авто-мэтчинге. Подробнее — [`address_suggestions.md`](./address_suggestions.md).

## 2. Геозоны работы

Геозоны (`CIRCLE`/`POLYGON`) и привязка исполнителя к рабочей зоне удалены
миграцией `037_unified_addresses_and_drop_geozones.sql`. Расстояние теперь
меряется напрямую между координатами подачи заказа и позицией исполнителя
(`executor_positions` / рабочая метка, см.
[`executor_map_and_geofencing.md`](./executor_map_and_geofencing.md)).

## 3. Авто-мэтчинг заказов (`MatchingService`)

Цикл запускает `worker.MatchingWorker` каждые 5 секунд под защитой лидера
(`worker/periodic.go`, блокировка `matching`); сам подбор — `MatchingService.MatchOrders`.
Автоподбор выключен по умолчанию: пока `auto_matching_enabled` не `1`, проход
ничего не делает и заказы берутся только вручную.

1. Берёт страницу заказов в `SEARCHING`, старые первыми (`GetPendingOrders`,
   не больше 200 за проход; остаток дойдёт в следующих тиках).
2. Берёт исполнителей с активной сменой.
3. Загружает всё нужное сравнению одним набором запросов на раунд: варианты
   услуг, заказчиков и исполнителей, позиции, число назначенных заказов и
   тихую блокировку (`PenaltyService.SilentlyBlockedAmong` — один запрос на
   раунд, а не на пару заказ–исполнитель).
4. Для каждого заказа ищет исполнителя без назначенного заказа, который
   проходит общий предикат допуска (`service/eligibility.go` — тот же, что у
   карты, списка и `Accept`) и находится не дальше `auto_match_radius_km`
   (по умолчанию 10 км). Исполнитель с неизвестной позицией не подходит.
5. Назначает (`orderRepo.Assign`, `status -> ASSIGNED`).

## 4. Отчёт о местоположении во время смены

Во время активной смены приложение исполнителя отправляет текущие координаты:
- Эндпоинт: **`POST /api/executor/shifts/location`** (`latitude`, `longitude`).
- `ShiftService.RecordLocation` сохраняет позицию через тот же путь, что и
  живая метка (`ExecutorGeoService`), — по ней автоподбор меряет расстояние.
- Коды: `409` — нет активной смены, `422` — негодные координаты, `500` —
  сервис собран без хранилища позиций.

### Смены

| Метод | Эндпоинт | Что делает и коды |
| :--- | :--- | :--- |
| `POST` | `/api/executor/shifts` | Открыть смену на 1, 3 или 5 часов. `409` — смена уже открыта, `422` — недопустимая длительность |
| `POST` | `/api/executor/shifts/end`, `/api/executor/shifts/early-end` | Завершить смену (оба пути — `ShiftService.End`). До планового конца — штраф `shift_early_exit_penalty`; при назначенных заказах штраф удваивается и включает их стоимость, заказы возвращаются в поиск. Снятие заказов, штраф и закрытие смены — одна транзакция, закрытие охраняется статусом: смену, которую тем временем закрыл воркер, штраф не догоняет. `409` — нет активной смены, `500` — сервис собран без реестра |
| `GET` | `/api/executor/shifts/active` | Активная смена, иначе последняя. `404` — только когда смен не было вовсе. Чтение смену не закрывает |

Истёкшие смены закрывает только `ShiftWorker` (раз в минуту, под защитой
лидера): `ShiftService.AutoEndExpiredShifts` — один `UPDATE ... RETURNING id`
по всем активным сменам, прошедшим `planned_end_at`.

Штраф за выход из геозоны (`geofence_penalty_amount`, счётчик
`out_of_zone_count`) ушёл вместе с геозонами. Штраф за досрочное завершение
смены — в [`financial_system.md`](./financial_system.md).
