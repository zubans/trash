# Адреса: подсказки DaData и структурное хранение

Документ описывает ввод и хранение адресов после перехода с Nominatim на **DaData** и отказа от строкового формата адреса.

---

## 1. Зачем менялось

Раньше адрес хранился одной строкой и разбирался обратно регулярным выражением — одинаковым на клиенте и на сервере:

```
^Россия,\s*([^,]+?),\s*([^,]+?),\s*д\.\s*(\d+)(?:\s+кв\.\s*(\d+))?$
```

Из этого следовали три проблемы:

1. Номер дома допускался только числовой, поэтому `12к1`, `10 стр. 2` и `5А` отклонялись **после** того, как пользователь уже выбрал адрес из списка подсказок.
2. Квартира жила внутри строки, и её приписывал клиент — сохранённое значение могло разойтись с тем, что видит человек.
3. У адресов, добавленных из профиля, не было координат вообще, поэтому такие адреса были невидимы для авто-мэтчинга.

Nominatim (OpenStreetMap) эти проблемы решить не мог: он не содержит квартир, требует отдельного запроса геокодирования после выбора адреса, а его публичный инстанс по условиям использования запрещает автокомплит (из-за чего запросы к нему на всю платформу троттлились до 1 rps).

## 2. Провайдер подсказок (`service.DaData`)

- Файл: [`backend/service/dadata.go`](../backend/service/dadata.go)
- API: `POST https://suggestions.dadata.ru/suggestions/api/4_1/rs/suggest/address`
- Ключ: переменная окружения **`DADATA_API_KEY`**. Если ключ не задан, `NewDaData()` возвращает `nil`.
- Таймаут HTTP-клиента — **4 секунды**: ввод адреса интерактивный, подсказка после следующего нажатия клавиши бесполезна.
- Запрос ограничен `locations: [{"country": "Россия"}]`, язык — `ru`, `count` по умолчанию `7` (максимум 20).
- Запросы короче 3 символов не уходят к провайдеру — возвращается пустой список.

`service.AddressSuggester` ([`address_suggest.go`](../backend/service/address_suggest.go)) — единственная точка входа для подсказок. **Fallback на Nominatim сознательно удалён:** он бы молча возвращал адреса без квартиры и с ненадёжным номером дома, то есть ровно ту поломку, ради которой всё и переделывалось. Если ключ не задан, ввод адреса честно отвечает `503`, а бэкенд при старте пишет в лог:

```
[address] WARNING: DADATA_API_KEY is not set — address suggestions will return 503 and registration cannot complete
```

> Геокодирование (`service.Geocoder`, `GET /api/geo/geocode`) по-прежнему работает через Nominatim с кэшем в `geocoding_cache` — оно используется для обратного разбора произвольных строк, а не для ввода адреса.

## 3. Модель адреса (`service.Address`)

Файл: [`backend/service/address.go`](../backend/service/address.go)

| Поле | JSON | Назначение |
| :--- | :--- | :--- |
| `Value` | `value` | Однострочное представление для показа. **Всегда собирается из частей**, никогда не разбирается обратно. |
| `Region` | `region` | Регион (`region_with_type`). |
| `City` | `city` | Город или населённый пункт. |
| `Street` | `street` | Улица (`street_with_type`). |
| `House` | `house` | Дом целиком, включая корпус и строение (`12к1`, `10 стр. 2`). |
| `Flat` | `flat` | Квартира/офис. |
| `FiasID` | `fias_id` | Идентификатор в ФИАС — стабильный ключ: два написания одного адреса имеют один `fias_id`. |
| `Lat` / `Lon` | `lat` / `lon` | Координаты, приходят вместе с подсказкой — второй запрос геокодирования не нужен. |
| `Source` | `source` | Кто выдал адрес: `dadata`, `nominatim`, `manual`, `legacy`. |

Методы:

- `Compose()` — собирает строку `Город, Улица, д. N, кв. M`. Это **единственное** место, где строится строка адреса, поэтому на всех экранах адрес выглядит одинаково.
- `IsDeliverable()` — есть город, улица и дом. Адрес до улицы можно показывать в подсказках, но нельзя принимать как адрес забора.
- `HasCoordinates()` — участвует ли адрес в мэтчинге по расстоянию.
- `WithFlat(flat)` — копия с квартирой и пересобранным `Value`.
- `Validate()` — понятная человеку причина отказа (`выберите адрес с номером дома из списка подсказок`).
- `ParseAddressLine(line)` — разбор строки. Применяется только к двум источникам: уже установленным мобильным сборкам и записям, сохранённым до появления частей.

## 4. HTTP-эндпоинты

| Метод | Путь | Ответ | Назначение |
| :--- | :--- | :--- | :--- |
| `GET` | `/api/geo/suggest?q=...&count=7` | `[]service.Address` (части раздельно) | Основной эндпоинт подсказок. |
| `GET` | `/api/geo/autocomplete?q=...` | `[]AutocompleteResult` (строка `Россия, Город, Улица, д. N`) | **Legacy.** Форма ответа сохранена ради установленных мобильных сборок: они перепроверяют строку своим регулярным выражением перед отправкой. Внутри теперь тоже DaData; подсказки без номера дома отфильтрованы, так как старый клиент их всё равно отклонит. |
| `GET` | `/api/geo/geocode?q=...` | `{latitude, longitude}` | Геокодирование через Nominatim с кэшем. |

Все три ограничены рейт-лимитером `geoLimiter` — **30 запросов в минуту** ([`backend/main.go`](../backend/main.go)).

### Коды ошибок (`writeGeoError` в [`handler/geo.go`](../backend/handler/geo.go))

| Код | Ошибка | Смысл |
| :--- | :--- | :--- |
| `503` | `ErrNoAddressProvider` | Провайдер не настроен — проблема деплоя, а не запроса. |
| `502` | `ErrAddressProviderUnreachable` | DNS/TLS/соединение до провайдера не поднялось. Осознанно **не** `422`: с введённым текстом всё в порядке. |
| `429` | `ErrGeocoderBusy` | Общий слот к апстриму не освободился вовремя. |
| `422` | прочее | Запрос действительно некорректен. |

## 5. Хранение (миграция 031)

[`backend/migrations/031_structured_addresses.sql`](../backend/migrations/031_structured_addresses.sql)

**`customer_addresses`** — добавлены `region`, `city`, `street`, `house`, `flat`, `fias_id`, `geo_lat`, `geo_lon`, `source` (`NOT NULL DEFAULT 'legacy'`) и частичный индекс `idx_customer_addresses_fias` по `fias_id`.

**`customer_profiles`** — добавлены `address_flat`, `address_fias_id`, `address_lat`, `address_lon`.

Колонка `address` остаётся как строка для показа, поэтому читающий её код менять сразу не требуется.

**Бэкфилл:** все уже сохранённые адреса обязаны были пройти старое регулярное выражение, поэтому их форма известна точно и разбор безопасен. Паттерн дома в миграции намеренно свободнее исходного — чтобы адреса, поправленные руками в БД, тоже разложились.

## 6. Совместимость с установленными клиентами

Приложение обновляется не у всех сразу, поэтому оба формата принимаются одновременно:

- **Регистрация** `POST /api/register` — `RegisterRequest` принимает и `address` строкой, и части (`region`, `city`, `street`, `house`, `flat`, `fias_id`, `source`). Если части не пришли, строка раскладывается на сервере (`ParseAddressLine`).
- **Адреса пользователя** `POST /api/user/address` — `addressRequest.toAddress()` предпочитает части и падает на разбор строки, если их нет. Квартира, присланная рядом со строкой, применяется — так её отправляет старый экран регистрации.
- **Legacy-подсказки** `GET /api/geo/autocomplete` — см. таблицу выше.

Проверка формата адреса при регистрации теперь смысловая, а не текстовая: требуется населённый пункт, улица и дом (`Address.Validate`), а не совпадение с фиксированным написанием.

## 7. Фронтенд

[`frontend/src/components/AddressAutocomplete.vue`](../frontend/src/components/AddressAutocomplete.vue) — одно поле адреса:

- ходит в `GET /geo/suggest`, отдаёт наверх `StructuredAddress` — ровно ту форму, в которой адрес хранится на бэкенде;
- **квартира вводится в том же поле**: после выбора дома под строкой появляется компактный ввод `кв./офис`, вместо отдельного поля где-то ещё на форме;
- клавиатурная навигация по списку (↑/↓/Enter/Esc), спиннер загрузки и кнопка очистки.

Компонент используется в [`Login.vue`](../frontend/src/pages/auth/Login.vue) (регистрация), [`CustomerDashboardV2.vue`](../frontend/src/pages/customer/CustomerDashboardV2.vue), [`CustomerProfilePage.vue`](../frontend/src/pages/customer/CustomerProfilePage.vue) и [`CustomerProfileModal.vue`](../frontend/src/pages/customer/components/CustomerProfileModal.vue).

Экран профиля исполнителя ([`ExecutorProfileModal.vue`](../frontend/src/pages/executor/components/ExecutorProfileModal.vue)) и админский [`UserList.vue`](../frontend/src/pages/admin/UserList.vue) пока используют legacy-эндпоинт и строковый адрес.

## 8. Конфигурация

| Переменная | Описание | Значение по умолчанию |
| :--- | :--- | :--- |
| `DADATA_API_KEY` | Ключ API подсказок DaData. Без него `/geo/suggest` и `/geo/autocomplete` отвечают `503`, регистрация невозможна. | — |

Ключ обязателен: в `docker-compose.yml` он объявлен как `${DADATA_API_KEY:?DADATA_API_KEY is required}` — без него контейнер бэкенда не поднимется. В CI/CD значение приходит из GitHub Secret `DADATA_API_KEY` и записывается в `.env` на сервере (`.github/workflows/deploy.yml`).
